## Technical Debt Ledger

| Date | Milestone | Debt | Reason | Paydown target |
| --- | --- | --- | --- | --- |
| 2026-05-15 | Planning docs | No production-code debt introduced. | This setup creates planning documents only. | Not applicable. |

| 2026-05-15 | Current code | Router currently records route cells directly from route nodes. | This can blur lattice-node and CM-tile-cell semantics. | Milestone M1. |
| 2026-05-15 | Current code | Raster-spine and line-support diagnostics are not yet first-class recovery artifacts. | Endpoint-only and equal-length route ambiguity needs source-line support. | Milestone M2. |
| 2026-05-15 | Current code | `CompiledTileCatalog` lacks the full pre-assignment feasibility oracle required by the recovery contract. | Routing and anchor selection must reject impossible direction sets before final tile assignment. | Milestone M3. |
| 2026-05-15 | Current code | Accepted routes do not yet update an explicit persistent `LinearNetworkState`. | The old graph kept hidden connection state; the typed path needs an inspectable equivalent. | Milestone M4. |
| 2026-05-15 | Current code | Anchor selection is still too close to nearest-cell snapping. | Legal CM intersections require tile-aware candidate scoring and split/failure planning. | Milestone M5. |
| 2026-05-15 | M0 | The network recovery helper uses a file-level ruff import-order/E402 waiver because tests extend `sys.path` before importing app modules. | Existing local test pattern imports app modules this way; changing global test import setup is outside M0. | Consider a shared test import/conftest cleanup outside network recovery milestones. |
| 2026-05-15 | M1 | Endpoint cells owned by fixed intersection variants can skip route-placement mismatch checks when the route endpoint's local straight-tile requirement is broader than the intersection tile. | Direct cell paths make endpoint cells visible to both route and intersection placement; a full connection-state validator is intentionally deferred. | Milestone M8. |
| 2026-05-15 | M2 | Raster-spine extraction scans the candidate bbox with Shapely cell intersections and has not been optimized for large real-world line batches. | M2 is correctness-first and fixture-scale; optimizing before route correctness stabilizes could hide semantic mistakes. | Milestone M12. |
| 2026-05-15 | M2 | Spine alignment is currently a routing cost and diagnostic, not a hard tile-feasible acceptance rule. | Tile catalog feasibility, persistent connection state, and final validation are owned by later milestones. | Milestones M3-M9. |
| 2026-05-15 | M3 | `best_tile` accepts `road_class` but does not yet use it for ranking. | M3 only establishes the feasibility oracle; class/priority-aware tile preference belongs with anchor and staged routing decisions. | Milestones M5-M7. |
| 2026-05-15 | M3 | Catalog-gap diagnostics are exposed as query helpers, not emitted as a global startup report. | The current typed pipeline does not have a dedicated startup diagnostic stage; tests can identify gaps and later orchestration can publish them. | Milestones M7-M11. |
| 2026-05-16 | M4 | Router commits accepted routes into `LinearNetworkState`, but A* neighbor expansion does not yet use state as a hard search constraint. | M4 establishes persistent state without widening into tile-feasible route search. | Milestone M6. |
| 2026-05-16 | M4 | `TileAssigner.assign(..., linear_state=...)` can consume state-derived direction unions, but default assignment remains compatible with route-local specs. | Existing pipeline and tests still depend on legacy-compatible endpoint handling until strict finalization is introduced. | Milestone M8. |
| 2026-05-16 | M5 | `SplitAnchorPlan` records legal split direction sets, but routing does not yet route individual incident edges to separate split anchors. | M5 makes split/failure planning visible without changing the route graph contract mid-milestone. | Milestone M6. |
| 2026-05-16 | M5 | Anchor scoring is intentionally simple: source distance, movement radius, catalog feasibility, and occupancy feasibility. It does not yet apply full road-class or raster-spine-aware scoring. | The milestone needed a stable planning contract first; richer routing constraints and class/stage policy belong to later milestones. | Milestones M6-M7. |
| 2026-05-16 | M5 | `NetworkRouter` now receives catalogs from `OSMProcessor`, but tile assignment still does not consume router `linear_state` in the public pipeline path. | Strict state-derived finalization remains deferred by the M4 ledger and M8 plan. | Milestone M8. |
| 2026-05-16 | M6 | A* enforces simple paths with an ancestry check during expansion, but the priority queue key remains current cell plus incoming direction rather than full path history. | Correctness is preserved for the covered small fixtures and prevents repeated-cell illegal unions; a more efficient/path-history-aware implementation should wait until correctness fixtures stabilize. | Milestone M12. |
| 2026-05-16 | M6 | Split-anchor plans are now consumed by routing, but final tile assignment and output validation do not yet prove that every split-intersection pattern preserves final-row connectivity. | M6 owns route endpoints and tile-feasible search; strict state-derived finalization and final output invariants are owned by later milestones. | Milestones M8-M9. |
